# v0.1.14 稳定性专项：审查修复与 v0.2 准备

> 目标平台：Unraid 7.2.2。保持 Tampermonkey **单文件、只读模式**，不增加任何 NAS 文件写入功能。

## 已实施的稳定性修复

1. **导航历史一致性**：统一 `writeUrl(path, replace)`、`navigate(path, addHistory, urlMode)`、`stepHistory()` 和 `restoreBrowserPath()`。文件管理器内部前进/后退使用 `replaceState`，避免产生多余的 Chrome 历史项；浏览器 `popstate` 只恢复视图，不反复压入新记录。
2. **首次初始化状态保护**：初始化期间标记 `state.initializing`；没有活跃标签时，历史导航直接返回；涉及目录的按钮适时禁用；首次选取默认共享目录后才创建真实标签；再次初始化有代际检查。
3. **目录读取请求隔离**：当前目录的请求使用 `AbortController`。切换目录会取消前一请求，并额外使用 `requestId / tabId / path` 校验响应是否属于当前目录。
4. **目录树去重与失败处理**：`treeLoads` 对同路径的并发加载做去重；失败不再用 `[]` 伪装成已成功读取的空目录，因此用户可展开重试。即使目录树读取落后于主内容读取，也不应覆盖后者较新的缓存。
5. **事件与资源清理**：全局鼠标、键盘、布局事件统一绑定可取消的 `lifecycle.signal`；为 `ResizeObserver`、滚动定时器、布局延迟任务和 MutationObserver 提供统一清理入口；离开页面时释放。保留 BFCache 情况下的浏览器自恢复能力。
6. **目录树点击区分**：展开按钮明确阻止事件冒泡，不依赖点击目标恰好是按钮还是内部 SVG，避免展开误触导航。

## 自动验证

- 单元测试：`node --test tests/*.test.mjs`，包括旧版状态/解析测试和新的请求取消、导航与清理检查。
- 真实浏览器交互：`node --test tests/e2e/*.spec.mjs`，在模拟 Unraid 页面上通过 Playwright Chromium 验证根目录默认选择、目录树展开、浏览器与内部历史、多选、LOCATION 弹层、列宽持久化以及错误后重试。
- 压力基准：`node tests/perf/benchmark.mjs`，对 100、1,000、10,000 项模拟目录分别记录冷启动完成时间、DOM 元素总数、浏览器 JS 堆占用和滚动尺寸。它是**测量工具而非性能承诺**；不同机器上结果会变动。
- GitHub Actions 的 `validate` 与 `browser-e2e` 两个 job 运行语法/单测、浏览器测试及基准。
- E2E 与基准都使用**本地虚拟 Browse 响应**，不会对真实 NAS 进行文件操作。

### 本地运行浏览器测试

```bash
npm install --no-save playwright@1.55.0
npx playwright install chromium
python3 -m http.server 8765 --bind 127.0.0.1 &
node --test tests/e2e/*.spec.mjs
node tests/perf/benchmark.mjs
```

## 现阶段仍然存在的限制

- 大型目录仍通过 `renderFiles()` 一次性创建全部行 DOM 和行事件监听。**如果 10,000 项测试显示明显高延迟或较大内存占用，v0.1.15 应当先引入虚拟列表**，不要直接开放写入。
- 目前是用户脚本注入 Unraid 的布局方式，不是 WebGUI 原生插件。真实 NAS 上的页面主题、折叠顶栏、额外插件及浏览器兼容仍需人工验收。
- 自动测试在模拟原生 Browse 响应上运行，不能取代真实 Unraid 的系统权限、符号链接、共享磁盘布局和文件操作安全验收。
- 当前没有跨浏览器/跨会话持久化标签历史；列宽和视图偏好仍使用浏览器本地存储。

## v0.2 模块化计划（本次不重构）

| 目标模块 | 职责 |
| --- | --- |
| `core/path.js` | 共享路径规范化、读操作合法性、未来写入参数声明 |
| `core/navigation.js` | 标签、浏览器历史、初始化及选择状态 |
| `api/browse.js` | 原生 Browse.php 只读响应解析、请求取消与缓存 |
| `api/operations.js` | 未来文件操作适配层（**当前不创建写请求**） |
| `ui/tree.js`、`ui/list.js` | 目录树与文件列表，隔离 DOM 和状态 |
| `ui/dialogs.js` | 操作确认、错误提示及长任务进度 |
| `styles/*.css` | 主题变量、布局和组件样式 |
| `src/main.js` | 依赖组合、生命周期与跨模块事件 |

构建时再使用 esbuild 等工具生成**一个**带 `// ==UserScript==` 元数据的脚本供 Tampermonkey 安装，避免用户在 NAS 上安装 Node.js 或额外服务。

### 正式开放文件写入前的安全门槛

- 研究 Unraid 7.2.2 `Control.php` 的准确请求字段、异步任务状态、取消/失败语义和权限机制；**不能把 `Browse.php` 的只读路径校验当成写入校验**。
- 实际写入端必须验证路径和权限，包括符号链接、目的目录、冲突覆盖和跨共享目录移动；前端校验只能提升体验，不能替代执行端检查。
- 所有破坏性操作需要明确确认和可审计的任务反馈。删除和替换最后开放，默认不覆盖原文件。
- 必须先在隔离的测试共享上验证重命名、复制、移动、权限异常、网络中断、任务重试，不能直接在 `appdata`、`system` 等重要共享上试验。
