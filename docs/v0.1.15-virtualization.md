# v0.1.15：大目录虚拟滚动与性能对比

> **运行环境**：GitHub Actions 的无头 Chromium、模拟 Unraid 7.2.2 Browse 响应。结果是浏览器端基准数据，不是实际 NAS 磁盘扫描或网络读取速度的保证。

## 设计原则

- **仅超大目录虚拟化**：当前目录经过筛选后的可见项目超过 200 时，渲染可视区域及前后各 8 行的缓冲区域；小于等于 200 项保持原有 DOM 渲染方式。
- **原生滚动条和固定表头**：列表仍使用原本的 `overflow:auto`，表头 `position:sticky`；前后占位元素保持完整滚动高度。
- **列表与网格均支持**：列表每行固定 38px；网格每行卡片高 122px、行间距 10px，滚动步长 132px，列数根据实际容器宽度计算。目录树、详情栏尺寸变化时由 ResizeObserver 调整可视范围。
- **数据不分页不裁剪**：`state.entries` 保留所有文件；排序和过滤结果缓存，不在滚动事件中重新排序。每一个可见 DOM 文件行保留在完整列表中的绝对索引。
- **交互一致**：跨窗口 Shift 连选、Ctrl/⌘ 多选、全部选择、重新显示已选行、双击/右键、LOCATION、列宽拖动和列表/网格切换继续使用原先事件逻辑。
- **只读、安全范围不变**：没有加入文件修改、上传、删除等 API。

## 首轮性能测量

| 模拟文件数 | v0.1.14 耗时 | v0.1.15 耗时 | v0.1.14 DOM 元素 | v0.1.15 DOM 元素 |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 165ms | 111ms | 1,430 | 1,430 |
| 1,000 | 707ms | 84ms | 13,130 | 445 |
| 10,000 | 44,752ms | 202ms | 130,130 | 445 |

新版本 1,000 和 10,000 项测试都只挂载约 24 个文件行；可访问完整目录中的最后一个文件，文件统计仍然展示全量数量。

- [v0.1.14 基准运行](https://github.com/nukewarrior/unraid-file-station/actions/runs/38041575744)
- [v0.1.15 基准运行](https://github.com/nukewarrior/unraid-file-station/actions/runs/38042406717)

两次测量分属不同 CI 运行，机器负载可能变化；这些数据说明的是“全量渲染”与“虚拟渲染”的明显数量级差异，而不是面向所有设备的稳定耗时承诺。JS Heap 指标不能代替 Chromium 全部 DOM/渲染内存占用。

## 验证覆盖

- `tests/core.test.mjs`：滚动窗口的范围、前后占位高度、网格列数、绝对索引及完整状态。
- `tests/e2e/browser.spec.mjs`：在 1,200 个文件目录中滚动至末尾并跨窗口 Shift 连选；在网格模式缩窄窗口并滚动到末尾。
- `tests/perf/benchmark.mjs`：100、1,000、10,000 项分别记录实际渲染耗时、DOM 元素、挂载行数、总数和滚动尺寸；并验证虚拟模式能滚动到最后一个文件。
- 性能压力测试不随每次提交重复运行。需要时可本地执行基准，或在工作流合并到默认分支后于 GitHub Actions 手动执行「大目录性能基准」。

## 未来注意事项

1. **行高需要保持一致**。如后续需要让网格文件名多行展示、自动调整卡片高度或增加进度条，应改成支持动态行高的虚拟模型；不能单独改 CSS 而忘记同步 JS 中的固定行高。
2. 大目录的初始 Browse 响应仍会返回完整 HTML，脚本仍然需要解析所有文件元数据。此次改进主要解决浏览器 DOM 数量和渲染瓶颈，**不解决服务器枚举耗时**。
3. 需要在真实 Unraid 7.2.2、多个主题、不同浏览器和大目录下再次验收；虚拟化测试不等于写入操作安全验证。
4. 当前每次进入新目录仍会重新加载元数据，暂不进行服务端分页或增量加载。
