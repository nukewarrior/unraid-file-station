# v0.2.16.2 — 真实 F5 恢复验收规程（尚未通过）

> 本文件定义验收边界；不表示已经完成真实 F5 验收。v0.2.16.1 的 10/10 synthetic-only 报告不是本阶段证据。

## 范围与前置条件

- 仅允许对 `/mnt/user/downloads/新建文件夹` 内的测试文件进行创建、移动、复制和清理。禁止清理整个授权根目录，禁止触碰其他 Share。
- 使用独立随机子目录（例如 `__ufs_f5_acceptance_<nonce>`）中的 source/target，操作前保留源文件并确认同名目标不存在。
- 确认原生 `mode=read` 无运行任务，`mode=jobs` 队列为空，当前页面只有一个 File Station 标签处于主动调度；任何未知原生任务均中止，不自动接力。
- 本阶段必须使用 File Station **正式 UI** 创建和提交任务，不可把直接调用 `copyNativeEntry` 或生命周期探针当作恢复验收。
- 在触发 F5 前采集本地 taskId、操作、全部源路径、目标目录、submission、队列顺序与原生活动签名。刷新前后任何敏感令牌不得写入诊断报告。

## 用例和通过标准

| 用例 | 操作 | 必须观察到的行为 |
| --- | --- | --- |
| F5-COPY-RUNNING | 用正式 UI 复制足够大的测试文件，确认原生活动槽已出现精确 action/source/target，再按 F5 | 原生执行不被取消，不额外提交第二次；同一个 taskId 唯一关联，显示执行或待核实；完成事件+目标核验后才成功 |
| F5-COPY-GAP | 复制提交后、活动槽采样前刷新 | 找不到唯一原生候选时进入待核实，绝不自动重发 |
| F5-MOVE-RUNNING | 用正式 UI 移动本轮独立源，活动时 F5（若移动太快无法命中，不算通过） | 已提交意图不重复执行；源/目标状态和原生事件共同决定最终状态 |
| F5-BATCH-MOVE | 仅在已有原生批量移动路径满足前置条件时执行多文件移动并 F5 | 完整 CR 分隔源列表和目标精确匹配；任何单项/子集匹配不可接管；逐项核验 |
| F5-DUPLICATE-SIGNATURE | 使用隔离的合成测试模拟两个保存意图同签名，**不得以真实重复移动制造冲突** | 标记 ambiguous，不接管、不重试、不自动完成 |
| F5-UNATTRIBUTED-QUEUE | 原生队列存在不能明确归属的任务（优先用只读模拟，真实测试须确认归属） | 不调用 mode=start、不删除队列项、不抢占、状态保留为待核实 |

## 必须保留的证据

1. 测试前后 UI 诊断 JSON；每条用例的本地 taskId、全部文件路径、原生 read/jobs 快照、刷新前后时间戳。
2. 请求计数与方向：`mode=file` / 正式原生文件提交 / `mode=start` 的调用次数；注明拦截可见范围，**观察不到请求不能直接证明没有请求**。
3. 完成事件是否发生；如果 F5 导致事件丢失，写 `eventMissed=true` 并保留 `unknown`，不能因为原生活动槽变空、目标同名存在或大小一致就宣布成功。
4. 每个文件目标存在、类型、大小，以及移动时源是否消失；文件大小校验不等价于 SHA-256 完整性。
5. 恢复匹配结果：unique-signature-candidate / ambiguous / unmatched / unattributed；被拒绝时的诊断码和原始证据（脱敏）。

## 阻断条件及失败处理

- 任一原生任务来源不明、候选数不是 1、保存意图缺失或提交结果不确定：停止后续操作，保留现场，不重发。
- 发生多标签并发调度、原生队列读取失败、目标冲突、报告缺少关键字段：本轮记为 blocked / inconclusive，不计 passed。
- 禁用全局停止（action=99）、按队列行号撤销（mode=undo）和模糊匹配后的清理；测试目录清理必须确认独立目录所有权、空闲状态及内容白名单。
- 先验证 F5-COPY-RUNNING，后做其它用例；任何实际安全问题优先修复，不扩大测试范围。

## 与既有测试的区别

- `v0.2.15.1` 一键验收证明部分正式复制/移动执行函数与原生队列阻塞逻辑，不覆盖真实 UI、F5 和 IndexedDB 恢复。
- `v0.2.16.1` 一键身份自测覆盖十个 synthetic-only 匹配场景，不读取 NAS、不验证运行中的原生任务。
- `v0.2.13.x` 生命周期探针覆盖原生执行在刷新后的继续运行，不等同于生产任务恢复状态机正确。
- 本阶段只有实际经过 UI/F5 及诊断证据审核的用例才标记通过。
