# v0.2.15.2 一键实机自动验收与历史报告清理

在 Unraid Shares/Browse 页面进入 **诊断日志 → v0.2.15 一键自动验收 → 开始一键验收**。

只需点击一次开始按钮并确认当前没有其他文件管理操作。工具会自动创建目录、写入合成文本、通过正式 File Station 复制/移动函数执行、核验、验证原生队列防越队行为，然后尝试清理目录及导出报告。无须人工逐项拖拽或切换原生文件管理器。

## 测试范围

独立工作目录：`/mnt/user/downloads/新建文件夹/__ufs_probe_v215_时间_随机数`。

| 阶段 | 自动执行 | 结果验证 |
| --- | --- | --- |
| 预检 | 检查原生活动槽为空、`mode=jobs` 原生队列为空，本地 File Station 无等待/运行/待核实文件任务 | 不满足直接中止 |
| 准备 | 新建独立 `source/` 与 `target/`，写入所有权标记与 4 个独特文本文件 | 回读内容匹配 |
| 单文件复制 | 调用生产 `copyNativeEntry` 复制 batch-a.txt | 目标内容一致，源文件仍在 |
| 多文件串行复制 | 调用相同生产函数复制第二个普通文件 batch-b.txt | 两个复制结果都已验证；这不是“真正原生批量复制” |
| 文件移动 | 调用生产 `moveNativeEntry` 移动 move.txt | 源已不存在、目标内容完全一致 |
| 原生占用防护 | 向原生队列添加唯一队列任务 | `assertNativeDispatchIdle` 拒绝继续 |
| 生产提交前防护 | 原生队列仍非空，尝试生产 `copyNativeEntry` | 在发出复制 POST 前拒绝，原队列身份未改变，目标未生成 |
| 受控收尾 | 严格确认唯一队列任务与空闲活动槽，仅调用一次 `mode=start` | 完成后队列清空、目标文件内容一致 |
| 清理 | 核验目录内容形状、所有权标记、原生活动槽和队列 | 只删除本次专属工作目录 |

自动导出报告文件：

`unraid-file-station-v0215-acceptance-YYYYMMDD-HHMMSS.json`

其中 `checks` 汇总已验证、未测试的功能；`steps` 给出每一步结果；`uncertain` 和 `cleanup` 提供安全状态。若清理跳过，**不要贸然删除仍被原生队列引用的目录**，可将报告发给开发者分析。

## v0.2.15.1 遗留测试目录安全清理

若已经跑过 v0.2.15.1，出现 `checks` 全部验证、`uncertain=false`，但是 `cleanup=skipped_or_failed`、`cleanupReason=目录无效或没有访问权限`，是因为该版本使用了不适用的旧目录检查器，不代表复制或移动失败。

**不需要在 NAS 终端执行 rm -rf。** 更新到 v0.2.15.2 后：

1. 打开 **诊断日志 → v0.2.15 一键自动验收**。
2. 点击 **导入旧验收报告并安全清理**。
3. 选择先前下载的 `unraid-file-station-v0215-acceptance-*.json` 文件。
4. 脚本先解析 JSON 并验证工作目录严格位于授权根目录，确认为 `__ufs_probe_v215_*` 形式、六项核心测试成功且原先没有不确定操作。
5. 核对对话框里**唯一的测试工作目录**，确认后读取 NAS 的原生活动槽、等待队列、所有权标记、`source/` 和 `target/` 全部文件的精确内容。包括源文件 `move.txt` 已不存在，目标文件 `move.txt` 存在。
6. 只有验证全部通过才执行原生删除**该目录本身**，随后自动下载更新的 JSON 报告。遇到异常会保留目录，不对陌生路径或数据进行删除。

这是一次**用户明确授权的清理操作**；不会因为选择报告就自动删除，也不会对队列执行 `mode=start`、全局停止或者重做原来的复制移动。

常规一键验收现在也使用同一套专属安全清理规则，完成后通常应显示 `cleanup=completed`、`result=passed`，但仍需要实机验证。

## 保护措施

- 只在显式授权的目录内创建和操作合成文件；原有 MP4 / ZIP 不会被读取、移动或删除。
- 不使用 `action=99` 全局取消，也不通过不稳定的行号删除原生队列。
- 如果服务器中出现其他活动任务、陌生排队项、无法识别的队列结构或网络读取失败，停止并保留现场。
- 测试期间不要在其他 WebGUI 标签页、其他客户端同时操作文件：Unraid 原生文件管理器没有跨浏览器原子独占锁。
- 本工具**不负责**测试多标签分布式锁、完整 UI/IndexedDB 排队流程、F5 恢复或断开所有网页后继续排队的行为；这些有独立专项测试。不能因为这次按钮通过就声称所有队列架构已验收。
- 最后仅保留测试报告。更新此版本不要求删除或重建 IndexedDB。
