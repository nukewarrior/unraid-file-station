# 原生任务生命周期专项测试（v0.2.13.8）

此工具是继 [原生基本能力探针](native-capability-probe.md) 之后的专项测试。目标是用用户已授权的实机大视频文件观察 **正在复制时原生入队、F5 刷新后的状态重连、队列在打开网页的条件下是否推进，以及缺乏历史回执的问题**。

## 运行入口

1. 更新 Tampermonkey 用户脚本至 `v0.2.13.8`。
2. 打开 Unraid File Station 的 `/Shares/Browse` 页面。
3. 点击 **诊断日志 → 任务生命周期测试 → 开始生命周期测试**，阅读并确认安全提示。
4. 保持当前浏览器标签页打开；**测试会自动刷新本页面一次**，刷新后会自动恢复状态观测。
5. 完成或发生可识别异常后，浏览器会自动下载 `unraid-file-station-lifecycle-probe-*.json`；也可通过测试面板点击“下载已有报告”。
6. 将 JSON 报告提供给 AI/开发者。不要把完整内部目录和浏览器环境信息发给不可信对象。

## 数据操作授权边界

用户明确授权：`/mnt/user/downloads/新建文件夹` 内可以进行测试数据操作。

本专项工具采取更保守的原则：

- 现有 MP4（64 MiB 至 2 GiB）**只读、不移动、不删除**；自动选择此授权目录及其下一层子目录内可见且路径经 Browse.php 确认的最大视频作为源文件。
- 所有写入、排队复制的目标、临时合成数据和最终清理均位于独立目录 `/mnt/user/downloads/新建文件夹/__ufs_lifecycle_时间_随机数/`。
- 目录内包含 `owner.txt`、`source/queue1.txt`、`source/queue2.txt`、`large/`、`queue1/` 和 `queue2/`。
- 大视频复制会临时占用与源视频相当的存储容量；需要 NAS 有足够空闲空间。
- 不调用 `action=99` 全局取消，也不使用 `mode=undo` 按行删除队列。
- 清理前确认活动任务为空、队列为空、唯一所有权标记匹配、子目录无未知项目；任何条件不满足就保留测试目录以便人工核实。

## 测试过程

1. 读取旧版 HTML / 新版 JSON 原生队列，并确认全局原生活动槽空闲、队列为空，File Station 自有任务也未运行。
2. 原生新建专用临时目录，生成唯一文本标记和两个小型排队源文件。
3. 启动原生 `action=8` 大视频复制，**必须观察到活动槽内的确是本次复制**，才继续后续动作。
4. 在大视频复制仍运行期间，向原生 `mode=file + task` 队列依次追加两个合成文本复制任务；每次严格核对原生排队任务的源、目标、唯一标识及队列中无外部任务。
5. 确认两项均已入队，写入 `sessionStorage` 检查点，然后自动 F5。
6. 新页面自动读取原生活动槽、排队列表和目标文件大小；记录采样时间线，观察队列任务是否被 **仍打开的 WebGUI** 自动推进。
7. 若大文件复制结束、全局活动槽空闲，队列在 6 秒内仍无推进，先记录“未观察到自动推进”，再仅在队列**完全由本次测试的任务组成**时调用 `mode=start`，最多两次。
8. 确认队列为空、目标大视频大小与源视频相同，并回读两个小型文本文件内容；记录源文件大小与修改时间有无变化。
9. 安全清理专属临时目录并下载 JSON 测试报告。

## 如何解读

- `conclusion.runningEnqueue = verified`：至少一次实际观察到大视频原生活动槽运行，同时成功把两个任务追加到原生队列。
- `conclusion.f5OverlapObserved = true`：刷新前最后一次采样同时看到了原生活动任务和未完成队列。
- `conclusion.f5Resume = verified_inflight_reconnected_and_completed`：刷新前有活动任务与队列重叠，刷新后重新连接并观察到测试结果；**这不是完整的逐字节校验**。
- `conclusion.f5Resume = verified_post_refresh_state_only`：刷新前最后一次采样未见到活动任务与排队任务重叠，只能证明刷新后的状态可查询，不能证明复制期间真正跨越 F5。
- `conclusion.automaticQueueAdvance = observed_with_browser_open`：没有手动推进便观察到后续队列执行，可能由另一个打开的 WebGUI 前端触发，**不能证明关闭所有网页后仍会推进**。
- `conclusion.automaticQueueAdvance = not_observed_with_browser_open`：观察到一段无原生活动任务的等待且队列未推进，之后脚本尝试严格核实身份后手动推进。
- `conclusion.largeCopy = file_size_matches_not_hash_verified`：仅文件大小相同，并不能保证二进制内容完全一致。
- `scope.videoSourceReadOnly = true`：本测试没有向原视频源文件提交写入命令。

## 限制和风险

Unraid 原生文件任务依赖全局活动槽和文件队列，没有跨浏览器原子独占锁。**必须在没有其他用户、其他标签页或其他文件任务时运行**。过程中不要手动切换文件管理器或操作任务队列。

大型复制可能比预期快，导致活动槽未被采样到；此时会保守停止而不构造虚假的“运行中入队”证据。复制任务已提交但尚未确认时，也可能保留测试数据。请查看报告中的 `workspace`、`uncertain`、`cleanup`、`cleanupReason`，不要盲目清除或重跑。

本专项**不能**直接证明完全关闭 WebGUI 后队列还能无人值守推进；也**不会**尝试全局取消、真实删除现有视频、SHA-256 内容比对或跨磁盘迁移。这些需要单独设计测试流程和保护措施。
