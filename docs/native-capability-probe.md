# 原生文件管理能力实机测试（v0.2.13.6）

本功能用于在重构 File Station 任务架构前，验证**当前 NAS 真实安装版本**的 Unraid File Manager 行为。不会调用 Docker、终端或第三方服务；通过浏览器里的 Unraid 原生 `Control.php` 与目录浏览接口执行。

## 运行方法

1. 在 Tampermonkey 更新 Unraid File Station 到 **0.2.13.6**。
2. 使用 Unraid 管理页面打开任意 Shares/Browse 的 File Station 视图，点击右上角 **诊断日志** → **原生能力测试**。
3. 确认 NAS 没有其他文件操作，且其他浏览器标签页或用户暂时不会使用原生复制、移动、删除或队列；点击 **开始安全测试** 并确认提示。
4. 保持当前页面打开。结束时浏览器**自动下载** `unraid-file-station-native-probe-*.json` 报告；浏览器若拦截自动下载，请允许当前站点下载文件。
5. 将 JSON 报告发给开发者或 AI 继续分析。不要复制其中的 CSRF Token、Cookie 或真实业务数据；报告不会记录这些信息。

## 严格限定的写入范围

唯一允许的数据操作根目录：

```text
/mnt/user/downloads/新建文件夹
```

每次运行创建随机且难以碰撞的独立目录：

```text
/mnt/user/downloads/新建文件夹/__ufs_probe_<时间与随机数>/
  probe-owner.txt
  source/   # 新建合成文本文件
  target/   # 只放合成测试结果
```

不会读取、复制、移动、修改或删除用户原有 MP4；只会在专属目录内生成很小的合成文本。所有操作均限制在上述路径内。不会执行原生的全局停止 `action=99`，也不会按队列编号撤销其他任务。

**警告：** Unraid 原生文件管理使用**全局活动任务槽和共享队列，缺少跨标签页原子独占锁**。探针在每次操作前检查空闲，但无法完全消除其他页面同时提交任务的竞争窗口。因此必须在没有其他用户/浏览器文件任务的时间段运行；若检测到队列非空、任务被占用或身份不符，立即停止测试。

## 覆盖范围

| 测试 | 操作 |
| --- | --- |
| 原生状态读取 | `mode=read`、`mode=jobs` |
| 新建临时目录 | 原生 `action=0` |
| 合成文本文件创建/核对 | 原生 `mode=save`、`mode=edit` |
| 多文件批量复制 | 原生 `action=8`，多个源路径以 CR 分隔 |
| 复制遇同名文件 | `--ignore-existing` 跳过，以及覆盖 |
| 同名目录合并 | 原生 `action=3`，分别验证内部同名跳过与覆盖、目标独有文件保留 |
| 同共享普通文件移动 | 原生 `action=9`，校验源消失及目标内容 |
| 原生队列单任务 | `mode=file` 携带 `task` 入队、`mode=jobs` 核对归属、`mode=start` 手动推进并校验结果 |
| 进度证据 | 记录原生活动槽采样次数、完成事件和进度事件数量 |
| 自动清理 | 校验所有权标记、预期目录结构与原生空闲状态，再仅删除专属临时目录 |

**本轮不执行**：全局取消、按行号撤销队列、多个队列任务的无人值守自动推进、浏览器 F5 中断恢复、大体积视频吞吐量比较。这些涉及全局并发风险、长时间执行或需要实际浏览器刷新，必须另行设计受控专项测试，报告也会明确标记为 `not_tested`。

## 失败及清理策略

无论通过还是失败，都会尝试自动生成 JSON 报告。只有确认操作结果、确认原生空闲且队列为空、校验所有权标记和目录内容都符合预期，才执行临时目录删除。

若任务可能已经提交但结束结果未知、出现外部任务、目录新增非探针文件、所有权标记丢失或原生 API 响应异常，**不会强制删除文件或重发原生任务**。JSON 会给出 `scope.workspace`、`uncertain`、`cleanup`、`cleanupReason` 等供人工核实。此时不要在确认原生活动/队列状态前直接再次运行，也不要盲目删除临时目录。

若在测试过程中关闭或刷新网页，浏览器本轮 JavaScript 会被中断，**不能保证自动导出报告**，且 NAS 原生工作可能继续；请先检查 Unraid 原生任务与该临时目录。
