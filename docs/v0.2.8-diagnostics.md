# v0.2.8 浏览器诊断日志

该版本在纯 Tampermonkey 脚本中引入本地诊断功能，不依赖容器、服务器、额外 Unraid 插件或外部日志平台。

## 如何使用

1. 更新 Tampermonkey 中的 **Unraid File Station** 到 **0.2.10.3**，刷新 \`/Shares/Browse\` 或 \`/Main/Browse\`。
2. 顶部工具栏点击卷轴日志图标“诊断日志”（Lucide scroll-text）（在原生文件管理器模式下，也有“诊断日志”按钮）。
3. 一般问题可直接复现；如遇难以排查的细节，先点击“开启增强诊断（15分钟）”，再复现问题。
4. 出现异常时点击“标记问题”。标记会附上当前目录是否加载中、复制任务/队列状态、恢复锁等快照。
5. 点击“导出 JSON”，将文件发给 ChatGPT；日志不自动上传。
6. 不再需要日志时可手动清空。增强诊断 15 分钟后自动停止，刷新网页不会提前关闭。

## 内容与持久化

- 常规模式：页面/模式切换、复制预检、提交意图、原生接口返回、复制结果、队列检查点、持久化/恢复异常。
- 增强诊断：目录请求耗时、原生读取轮询、采样的 Nchan/rsync 进度状态，避免每条进度都落库。
- IndexedDB \`ufs-diagnostics-v1\` 独立于复制队列数据库 \`ufs-copy-queue-v1\`，数据库不可用时保留有限的本次页面内存日志。
- 默认保存近 **24 小时**、最多 **2500 条**，并异步清理。异常时日志系统不会中止文件操作。
- 导出包括 app 版本、浏览器标识、页面路由、当前任务状态快照、按时间排序的事件与可关联的 \`sessionId\`/\`tabId\`/\`taskId\`。
- 页面突然崩溃、断电、浏览器强制杀进程时，最后少量异步日志不能保证写入磁盘。

## 隐私与安全

- 默认不捕获 Cookie、CSRF Token、认证请求体、完整文件内容、网页源代码或目录 HTML。
- 日志写入前会对敏感字段、URL 和文件路径进行脱敏；路径/文件名变为该浏览器本地随机盐生成的 **非密码学哈希标识**。可用于关联相同路径，但不应视为绝对匿名化。
- 日志上传前建议使用文本编辑器检查导出的 JSON，尤其是 Unraid 原生异常文本可能携带自定义文件名。
- 不改变复制提交、锁、队列恢复或文件完整性判断。日志数据库出现问题也不应造成复制失败。
- 文件管理器之外的其它页面（例如 \`/Main\` 首页）不会主动注入诊断代码。诊断只覆盖当前激活脚本的页面上下文。

## 推荐排障步骤

复制问题：先进入诊断中心，开启增强诊断，复制文件并复现问题，标记问题，最后导出 JSON。ChatGPT 可根据 \`queue.checkpoint\`、\`copy.submission_intent\`、\`native.request\`、\`copy.native_progress\`、\`queue.restore_assessed\` 等事件追踪提交与恢复是否发生。

界面问题：导出日志之外，最好补一张截图或短录屏。浏览器日志无法完整捕捉 CSS 布局的最终画面。

## 已知边界

- 仅能诊断本脚本可观察到的浏览器和 Unraid 原生状态，无法自动获得服务器上的 rsync 系统日志。
- 普通 \`DEBUG\` 事件需手动开启增强模式才能持久记录。
- 增强日志是采样数据，不等同于原生 WebSocket 所有原始消息的完整镜像。
