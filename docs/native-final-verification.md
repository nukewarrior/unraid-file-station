# 原生队列收尾验证（v0.2.14.1）

上一轮 v0.2.13.9 已验证：大文件 F5 后仍运行；原生 WebGUI 的前端事件会调用 mode=start 推进队列。但完全关闭所有页面后的队列接力、多标签页重复推进仍需要额外证据。

## 测试一：关闭所有页面之后

入口：**诊断日志 → 关闭页面后队列测试**。

1. 确认没有其他人或页面使用文件管理器，也没有其他原生排队任务。
2. 点击“准备关闭页面测试”。脚本将只读使用已授权目录中的一份 MP4，并在 /mnt/user/downloads/新建文件夹/__ufs_lifecycle_* 中创建复制目标及两项小型排队任务。
3. **一定要等状态提示“大视频仍在复制且队列有 2 项”**，然后立即关闭全部 Unraid WebGUI 页面，包括当前页面；不要仅刷新或最小化，不要留下其他设备浏览器使用 WebGUI。
4. 等至少 **30 秒**，用原来的浏览器配置重新打开 NAS 的 Shares/Browse 页面。进入同一入口，点击“关闭页面后读取结果”，确认确实关闭过全部页面。
5. 浏览器将下载 unraid-file-station-lifecycle-probe-*.json。此阶段**只读观察**，不会偷偷调用 mode=start，也不会重发任务。

**注意证据边界：** 浏览器关闭期间无法从已关闭页面观察服务器。重开后的首次采样如果仍看到排队任务、但没有活动任务，支持“无人接力时队列可能停住”；如果队列为空，不能证明是服务器自动推进，因为打开页面也可能促使原生 WebGUI 触发接力。

**如果队列仍在等待：** 请保留测试目录，不要手动删除或重复运行。原生任务队列非空时，脚本会拒绝新实验。更新到 **v0.2.14.1** 后，进入同一入口点击 **「安全完成遗留测试队列」**。此按钮只接受同一次测试自己的 **恰好两项排队任务**、原生活动槽为空、所有权标记和源文件完整的情形；经过单独确认后最多调用两次 `mode=start`。若有陌生任务、活动任务或请求结果不确定，立即中止且不删除数据。受控接力不会修改此前 `unattendedAdvance` 的独立观测结论。只有队列空、活动任务已停止、文件核验和目录归属检查全部通过才会自动清理专属目录。

## 测试二：多标签页被动监听

入口：**诊断日志 → 多标签页接力观测**。

1. 在同一 NAS 上打开两个 Shares/Browse 标签页。
2. 分别打开“多标签页接力观测”，点击“启动/加入监听”。两个标签页会加入同一会话，有效期 15 分钟；F5 后可恢复监听。
3. 在**已授权目录范围内**执行一项有持续时间的正常复制/队列实验。可以使用现有“任务生命周期测试”作为触发器，但**不要与上面的关闭所有页面测试同时运行**。
4. 点击“导出多标签报告”，得到 unraid-file-station-multitab-probe-*.json；在两个标签页分别停止监听。

脚本被动观察原生 XMLHttpRequest 调用 mode=start 的时间、发起页面实例及 HTTP 响应码。它不阻止、修改或发起任何原生请求，不记录 CSRF Token、Cookie 或请求正文。

报告中的“跨标签重叠”是 1 秒窗口内不同页面实例有多个 mode=start 请求的线索，**并不直接证明文件出错**。没加入监听的标签页/其他设备/非 XHR 请求都无法被本测试捕获。同一标签页刷新后也会产生新运行实例，不能简单把实例数量视为真实标签页数量。

## 数据安全

所有实际数据写入和清理范围严格限制在 **/mnt/user/downloads/新建文件夹** 内；源 MP4 仍为只读。不会调用全局停止 action=99 或按队列位置删除 mode=undo。若操作结果未知，保留现场。报告可能包含 NAS 内部路径与文件名，不建议公开发布未经检查的 JSON。
