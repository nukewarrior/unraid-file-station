# Unraid File Station

在 **Unraid WebGUI** 内提供接近 Synology DSM File Station 的文件管理体验，同时保留 Unraid 的顶部导航、Shares 设置页以及原生文件管理器。

> **开发状态：v0.2.3 单个文件与文件夹复制，针对 Unraid 7.2.2 设计。** 新建文件夹及重命名已实机验证；v0.2.2.1 自动刷新修复和本次复制仍待实机验证。
>
> 项目与 Unraid、Synology 均无官方关联。设计灵感来自 Synology DSM File Station。

## 已经实现

- 从 Shares 页每个共享旁边的 **蓝色 Browse 图标** 进入 File Station，自动定位到对应目录。
- 在 Shares 页增加独立 **FILE STATION** 按钮，打开左侧目录树中的第一个真实共享文件夹（不展示根目录列表）。
- 保留 Unraid 顶部导航与现有 Share 名称链接（Share 名称仍进入共享设置）。
- 在 Browse 页面中嵌入新的文件管理区域，不修改 Unraid 系统文件。
- 通过 Unraid 7.2.2 的 `/webGui/include/Browse.php` 读取真实目录，限定为 `/mnt/user`。
- 目录树（支持拖拽调整宽度）、目录标签页、面包屑路径、后退/前进、上一级、刷新。
- 列表/网格视图、当前目录过滤、文件夹优先排序；列表支持名称、大小、修改日期、OWNER、权限、LOCATION 六列及列标题排序、列宽拖动和持久化。
- 单选、Ctrl/⌘ 多选、Shift 连选、Ctrl/⌘+A、Escape 取消。
- 文件右键菜单、路径复制、单文件下载。
- 可选详细信息侧栏和两种主题（Unraid 融合 / DSM 经典）。
- 隐藏 Browse 页的重复原生面包屑与文件类型过滤器；根据 Unraid 顶部栏与底部状态栏自动计算页面剩余高度。
- 使用内置 SVG 图标并隔离 Unraid 全局按钮样式，保留目录真实大小写。
- 未接入的写入操作不出现在固定工具栏内，需要时通过「操作 → 返回原生文件管理器」完成。
- 一键切回原生文件管理器；可随时重新启用，回退状态保存在浏览器本地。

## v0.2.3：复制文件与文件夹

- 选中**单个**文件或文件夹后，可在右键菜单或顶部「操作」菜单打开「复制到…」，第一版不开放批量复制、移动、覆盖或自动重命名。
- 统一沿用新建/重命名弹窗视觉风格，并提供按需展开的目标目录树。虚拟根节点不能选择，目标限定 `/mnt/user` 下可访问的真实共享文件夹。
- 禁止选择原父目录、源文件夹本身及其内部子目录；复制文件夹时保留原文件夹名称，并保留原有源文件。
- 复制前重新读取源父目录和目标目录，拒绝源类型变化、目录不可读与同名目标。使用与其他写入操作相同的 CSRF、Unraid 全局任务预检查和本页面单任务写入锁。
- 原生接口使用 `Control.php`，复制文件夹 `action=3`、复制文件 `action=8`，`source` 保持无末尾斜杠，`target` 使用以斜杠结尾的**已存在目标目录**。由原生 rsync 负责实际复制；提供原生消息进度。
- 只有观察到原生任务运行或收到任务完成消息、并验证任务已经空闲及目标条目出现后，才报告完成。无进度连接或任务执行情况不明时显示「结果不确定」，不会自动重试；**不宣称进行了整个目录树的校验和验证**。
- **限制和风险**：Unraid 7.2.2 的原生 rsync `--ignore-existing` 可以跳过目标已有文件，却不能从根本上阻止目录合并或所有并发冲突；浏览器的前置检查不是原子操作。文件夹复制可能需要较长时间，复制中窗口不可关闭，且第一版不实现中途取消。
- 通过模拟 Browse/Control 接口的单元和浏览器测试验证，不会写入真实 NAS。首次测试仅使用**专用空测试 Share**，推荐分别验证文件、含嵌套文件的目录及同名冲突。

## v0.2.2.1：避免文件操作触发整页刷新

- 原因：原生 Browse.page 在约 3 秒后启动 `/sub/filemonitor` 监听；增强版自己调用原生 `Control.php` 时不会设置 `dfm.running=true`，因此原生监听会将自己的任务误当成外部操作，调用 `refresh()` -> `location.replace(location.href)`。
- 仅在 **增强 Browse 界面** 接管原生 `filemonitor` 实例，阻止其延迟启动或已启动订阅触发整页重载。保留原生全局 `refresh()` 函数，不修改其他 Unraid 页面的行为。
- 使用独立的 `/sub/filemonitor` 订阅检测外部文件操作；在外部任务从运行状态变成空闲后，通过 File Station `refreshDirectory()` 局部更新当前目录。新建、重命名等本脚本自身操作由原有成功后刷新机制处理，避免额外刷新。
- 单次操作完成后短暂抑制迟到的自身文件变更事件。若外部程序恰好同时操作，共享的原生任务状态无法完全区分来源，这属于浏览器端方案的已知边界。
- 原生文件管理器模式不接管监听器；切回原生时使用页面重新加载恢复完整原生逻辑。该修复不涉及虚拟滚动或目录读取性能优化。
- 新增浏览器模拟回归：验证原生 3 秒延迟启动被屏蔽、外部文件变更只刷新当前目录、新建文件夹与重命名不触发真实主文档网络导航。

## v0.2.2：文件及文件夹重命名

- 保持**纯 Tampermonkey UserScript**，不增加服务端、插件或容器。
- 单选项目时可从文件右键菜单、顶部「操作」菜单或 `F2` 进入重命名；多选、Share 根节点不可重命名。文件默认选中主文件名（保留扩展名），文件夹选中整个名称。
- 弹窗沿用已确认的新建文件夹视觉样式，展示当前路径、原名称与新名称。Enter 提交、Escape 取消。只有重命名成功后才刷新当前目录。
- 使用 Unraid 7.2.2 原生 `mode=file`，文件重命名 `action=7`，文件夹 `action=2`，要求有效 CSRF；前置检查源文件存在、源类型符合预期、新名称合法且父目录中没有目标。
- 与新建文件夹共用**单个 UserScript 写入锁**，并通过 `mode=read` 检查 Unraid 全局任务；任务完成后必须重新读取父目录验证旧名称消失且新名称出现。结果不确定时禁止再次在同一弹窗提交，不会自动重试。
- 文件夹重命名成功后，修正此浏览器中打开的子目录标签、标签内历史、目录树展开状态和当前 URL；旧浏览器历史路径在当前页面会话内跳转到新路径。目录树的旧异步读取结果会被丢弃。
- **重要风险**：原生重命名使用 `mv -f`，并没有原子级“不覆盖”选项；即使提交前检查目标不存在，其他进程仍可能在检查后创建目标而发生覆盖。纯 UserScript 无法完全消除并发竞态、符号链接风险或跨标签原生任务占用问题。
- 单元测试与 Playwright 采用模拟原生接口，不会重命名真实 NAS 文件。请首先在**专用空测试 Share** 实机验证；避免对 `appdata`、`domains`、`system` 等重要目录直接尝试。

> v0.2.2 不开发批量重命名，也不开放主动覆盖。同名冲突默认拒绝；原生接口固有的竞态风险仍需使用者了解。

## v0.2.1：新建文件夹（纯 UserScript，复用原生接口）

- 保持单文件 Tampermonkey 安装方式。文件工具栏新增「新建 → 新建文件夹」，提供紧凑弹窗、路径、名称与执行状态。
- 新建文件夹是**唯一启用的写入功能**；复制、移动、重命名、删除及上传仍未开放。
- 操作前重新读取父目录，拒绝已有同名文件或目录；写入名称校验 UTF-8 255 字节长度、路径边界与可能破坏任务文件编码的危险字符。
- 复用 Unraid 7.2.2 `POST /webGui/include/Control.php`：`mode=file, action=0`，显式携带 `csrf_token` 并沿用原生二次 URL 编码；使用 `mode=read` 检查任务是否被占用，监听 `/sub/filemanager` 进度。
- 原生接口 HTTP 200 或 `done` 事件都不意味着创建成功；轮询任务状态并重新读取目录，确认新文件夹出现后才报告成功。
- 请求结果不确定时禁止在同一弹窗再次提交，也不会自动重试；用户应先手动刷新检查。
- **安全边界**：Unraid 原生 `mkdir -p` + `chown -R` 在竞态条件下可能修改已存在目录的所有权；原生任务状态是全局共享的，没有原子锁；前端校验无法彻底消除并发竞态与符号链接穿越。
- CI 通过模拟 Browse/Control 接口测试，不会操作真实 NAS。首次实机创建仅建议在 **专用空测试 Share** 中进行；不要先在 appdata、domains、system 或重要业务目录尝试。

> v0.2.1 在用户自行安装后会实际执行新建文件夹。开发期间没有接触真实 NAS，使用前请先在隔离共享目录验证。

## v0.2.0：纯 UserScript 文件操作基础框架（无真实写入）

- **部署方式不变**：仍然只有一个 Tampermonkey UserScript，不安装 Unraid 插件、Docker、后台进程，也不修改 WebGUI 的 PHP。
- **操作计划与路径校验**：为新建文件夹、重命名、复制、移动、删除建立独立预览模型；限制在 `/mnt/user/<共享文件夹>` 中，拒绝直接操作共享根、相同源/目标、目录嵌套移动与覆盖策略。原生 `Control.php` 存在额外解码和任务分隔符，因此写入预览还拒绝 `%`、反斜杠、CR/LF、控制字符等有风险的路径。
- **原生接口描述**：记录 Unraid 7.2.2 `POST /webGui/include/Control.php` 的 `mode=file`、动作编号与 `/sub/filemanager` 任务进度通道，但**不建立发送写入请求的代码路径**。描述不是可直接执行的请求，也未经过真实 NAS 的冲突与编码验证。
- **模拟任务协调器**：支持操作计划、显式确认、单任务运行、模拟成功/失败与状态查询。模拟执行器仅允许在明确启用的单元测试模式下注入；生产界面不提供执行入口。
- **继续只读**：`FILE_WRITES_ENABLED = false`，不显示新建/重命名/删除等可点击写入入口；原有浏览、滚轮、列表/网格虚拟化、多标签与原生回退保持不变。
- **安全边界**：浏览器校验不是服务端强制隔离，无法证实符号链接目标、消除目标抢占竞态，或隔离 Unraid 全局共享任务状态。未来要开放任何具体写入操作，须先按功能补充实际目标检查、CSRF、状态协调和针对测试 Share 的实机验证。对于原生接口无法可靠保证“不覆盖”的操作，不能仅凭前端检查就宣称安全。
- **测试**：增加 7 项单元测试，共 58 项；原有 Playwright 回归测试继续检查 UI 和滚动行为。此处的测试数量以源码内容为准，CI 结果见 Actions。

> v0.2.0 是技术基础版本，不意味着文件写入功能已经可用。下一个阶段才是新建文件夹的安全评估、交互和在隔离共享目录上的实际验证。

## v0.1.16：修复虚拟列表滚轮失控

- **仅处理滚动**：对虚拟化文件列表和网格应用局部 `overflow-anchor:none`，避免 Chromium 在前后占位高度变动时自行修正 `scrollTop`、反复触发滚动，导致轻滚一次却持续下滑。
- 保留原生滚轮、触控板和滚动条；不改变滚动速度、不拦截 `wheel` 事件。普通文件列表、目录树、Unraid 原生 WebGUI 的滚动行为不受影响。
- Playwright 新增真实鼠标滚轮测试：单次 `wheel(0,380)` 后持续观察约 900ms，验证列表和网格的 `scrollTop` 不再自动增加；同时验证文件列表总滚动高度稳定。
- **本版不优化目录读取**：`Browse.php` 的完整 HTML 请求、网络等待及目录解析流程与 v0.1.15 保持一致，后续另行设计。

## v0.1.15：大目录虚拟列表和网格

- **虚拟列表**：单目录超过 200 项时，不再一次性创建每个文件对应的 DOM 行；仅渲染当前可视区域加前后 8 行的缓冲范围。通过前后占位高度保持真实滚动位置、列表的原生滚动条和固定表头。
- **虚拟网格**：网格视图同样按可视区域创建卡片，并随右侧区域宽度动态计算列数；文件项恢复列表时重新应用六列宽度。
- **保持完整数据**：过滤、排序、选中、Shift 跨窗口连选、⌘/Ctrl+A 和 LOCATION 均针对当前目录的完整数据集，不把未显示在 DOM 里的文件当作不存在；滚出屏幕后返回时恢复高亮。
- **减少重复计算**：按目录数组、筛选词、排序列与方向缓存排序结果，滚动时只更新窗口范围，不重复解析目录或重新排序。
- **仍不修改写入**：无数据库变更、不新增文件操作 API；小目录继续沿用原来的普通列表/网格渲染。
- 新增纯函数窗口边界测试、Playwright 1,200 项真实滚动与跨窗口多选测试，及 100 / 1,000 / 10,000 项大目录性能基准。

**首轮 Chromium 实测：**10,000 项目录从 v0.1.14 的约 **44.8 秒 / 13 万 DOM 元素**，改善为 v0.1.15 的约 **202 毫秒 / 445 DOM 元素**；1,000 项则由约 707ms 降到 84ms。测试详情和局限见 [v0.1.15 性能报告](docs/v0.1.15-virtualization.md)。

> 虚拟渲染固定使用列表行高 38px 和网格行步长 132px。后续 CSS 如果修改文件行实际高度，需同步这两个常量及回归测试，避免滚动定位错位。
## v0.1.14：导航稳定性、异步加载及真实浏览器测试

- 首次进入目录时增加初始化保护，避免在尚未创建标签页时触发后退、前进、新标签等操作。

- 新增 **Playwright Chromium 浏览器 E2E** 测试，实际检验根目录选择、浏览器历史、目录竞态、多选、LOCATION、列宽保存和加载失败重试。
- 已在模拟目录进行 100、1,000、10,000 文件性能实测，其中 10,000 项约 44.8 秒。后续应先引入虚拟列表优化，再进入真实写入阶段。
- 常规 GitHub Actions 运行单元测试和浏览器 E2E；大型目录基准已独立为手动工作流（合并到默认分支后可在 Actions 触发）。当前开发分支也可本地运行 `node tests/perf/benchmark.mjs`。

本次不改变 File Station 的外观、已有只读功能以及 NAS 部署方式。具体变更、真实测试记录和 v0.2 接口安全计划见 [v0.1.14 稳定性审查文档](docs/v0.1.14-stability.md)。
## v0.1.13：不可选的共享根分组与首次默认共享目录

- **所有共享文件夹只是分组**：左侧根节点仍可通过展开箭头展开或收起，但点击根节点文字不会导航或出现当前目录高亮。
- **首次默认目录**：从 Shares 页独立入口、直接访问 `/Shares/Browse?dir=/mnt/user` 或无 `dir` 参数时，先读取原生 Browse 返回的共享列表，再取左侧目录树顺序中的第一个有效共享目录打开（例如 TimeMachine），不依赖硬编码名称，也不按右侧文件列表的排序挑选。
- **无根目录闪屏**：取得共享列表后才创建标签页、加载对应共享内容。进入第一个共享时通过 `history.replaceState` 更新 URL，避免浏览器后退再次落在无法打开的根分组。
- **标签与导航一致**：新建标签默认打开第一个共享目录；已有深层链接、已有标签切换继续保持原路径；面包屑的「共享文件夹」只读不可点击；在共享根目录上禁用「上一级」。
- **容错**：无共享目录时显示空状态，不生成虚假的根标签；根读取失败时显示错误并允许刷新重试。第一个共享目录无法读取时保留可切换的目录树入口。
- 保留 Unraid 顶部导航、两主题、列宽/LOCATION、多选、原生文件管理器回退和只读安全边界，不修改数据库或 Unraid 系统文件。

> 自动测试只能验证默认路径的计算和导航约束；还需在真实 Unraid 7.2.2 浏览器里验收根目录加载顺序、历史记录与闪屏行为。
## v0.1.12：列表滚动条与表格宽度边界优化

- **消除不必要的横向溢出**：表头和文件行使用统一的 `width:100%;min-width:var(--ufs-table-min-width);box-sizing:border-box`，不再使用 `width:max(100%,...)`。表格最小宽度仍然等于六列的配置宽度之和、五处间距和左右内边距；容器有足够空间时不应该出现横向滚动。

- **滚动尺寸诊断**：加入对 `clientWidth`、`scrollWidth`、可用高度、最小表格宽度和保存列宽的只读诊断函数及测试。在真实 NAS 上需确认水平溢出确实消失；如果历史保存列宽较大，可使用右上角菜单「重置文件列表列宽」。

1. 在浏览器中安装 Tampermonkey 或其他兼容的用户脚本管理器。
2. 打开 `src/unraid-file-station.user.js` 的 Raw 地址，安装脚本。
3. **建议在用户脚本管理器中将匹配地址收窄为自己的 NAS 主机名或 IP。** 默认规则匹配任何主机上的 `/Shares*` 路径，仅为兼容不同 Unraid 主机名。
4. 打开 Unraid 7.2.2 的 **SHARES** 页，点击共享名称左边的蓝色浏览图标；或者点击 Shares 下方新出现的 **FILE STATION** 按钮。

示例：如果你的 Unraid 地址是 `http://tower`，可将用户脚本头部的通用匹配规则改为：

```javascript
// @match        http://tower/Shares*

```

如果使用 IP、端口、HTTPS 或自定义域名，请相应调整。不要直接使用示例地址覆盖自己的 NAS 地址。

## 开发与测试

- 代码：`src/unraid-file-station.user.js`，纯原生 JavaScript，无第三方运行依赖。

- 自动检查：`node --test tests/*.test.mjs`。

建议在真实 Unraid 上分别测试目录名含中文、空格、引号、括号与特殊字符的情况，浏览器返回行为，以及白色和黑色 WebGUI 主题。只读版不应更改 NAS 端任何文件。

## 技术与安全原则

- **不更改 Unraid 系统文件**，通过浏览器用户脚本实现可逆接入。
- **只读优先**：当前所有文件操作请求只有 GET 目录请求；下载采用原生文件 URL，写入功能暂不调用 `Control.php`。
- **路径边界**：只允许 `/mnt/user` 及其子目录，不让用户共享与物理磁盘路径互相拖放。
- **视图与数据隔离**：动态文件名使用 `textContent` 渲染，不直接拼入 HTML 字符串。
- **同源请求**：使用已有 Unraid 登录会话，无第三方上传或数据收集。
- **回退开关**：浏览器保存用户偏好，关闭/卸载脚本立即恢复原生 WebGUI。
