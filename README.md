# Unraid File Station

在 **Unraid WebGUI** 内提供接近 Synology DSM File Station 的文件管理体验，同时保留 Unraid 的顶部导航、Shares 设置页以及原生文件管理器。

> **开发状态：v0.2.6 复制同名文件忽略／覆盖策略，针对 Unraid 7.2.2 设计。** v0.2.5.1 已通过实机验收；v0.2.6 待实机验收。
>
> 项目与 Unraid、Synology 均无官方关联。设计灵感来自 Synology DSM File Station。

## 已经实现

- 从 Shares 页每个共享旁边的 **蓝色 Browse 图标** 进入 File Station，自动定位到对应目录。
- 在 Shares 页增加独立 **FILE STATION** 按钮，打开左侧目录树中的第一个真实共享文件夹（不展示根目录列表）。
- 保留 Unraid 顶部导航与现有 Share 名称链接（Share 名称仍进入共享设置）。
- 在 Browse 页面中嵌入新的文件管理区域，不修改 Unraid 系统文件。
- 通过 Unraid 7.2.2 的 `/webGui/include/Browse.php` 读取真实目录，限定为 `/mnt/user`。
- 目录树（支持拖拽调整宽度）、目录标签页、面包屑路径、后退/前进、上一级、刷新。
- 列表/网格视图、当前目录过滤、文件夹优先排序；列表支持名称、大小、修改日期、OWNER、权限、LOCATION 六列及列标题排序、列宽拖动和持久化。
- 单选、Ctrl/⌘ 多选、Shift 连选、Ctrl/⌘+A、Escape 取消。
- 文件右键菜单、路径复制、单文件下载。
- 可选详细信息侧栏和两种主题（Unraid 融合 / DSM 经典）。
- 隐藏 Browse 页的重复原生面包屑与文件类型过滤器；根据 Unraid 顶部栏与底部状态栏自动计算页面剩余高度。
- 使用内置 SVG 图标并隔离 Unraid 全局按钮样式，保留目录真实大小写。
- 未接入的写入操作不出现在固定工具栏内，需要时通过「操作 → 返回原生文件管理器」完成。
- 一键切回原生文件管理器；可随时重新启用，回退状态保存在浏览器本地。

## v0.2.6：复制同名项目的忽略／覆盖策略

- 在已确认的 465px 复制目标弹窗内，目标位置下方增加紧凑的「遇到同名项目：忽略 / 覆盖」，默认忽略。说明仅在鼠标悬浮或键盘聚焦时展示 Tooltip，**不出现常驻的覆盖警示条**，原有目录树、行内新建、橙色按钮和窗口尺寸规则不变。
- 使用 Unraid 原生 Control.php 的 `exist` 参数：**忽略**对应 rsync `--ignore-existing`；**覆盖**允许原生 rsync 更新目标同名文件。对已经存在的顶层普通文件，忽略模式不提交原生写入；对同名文件夹仍发起任务，以便合并新内容。
- 原生目录返回的源、目标类型不匹配或路径不可信时，继续在写入前阻止；源目录自身/子目录不能作为目标；批量复制先做整批类型冲突预检，再按各项顺序执行。
- 单文件忽略时明确显示「已忽略同名文件」；批量清单区分成功和忽略，进度将已忽略项目计入已处理数量。**批量统计只精确到顶层所选项目**，不宣称能统计文件夹内部被 rsync 忽略或覆盖的文件数。
- 多个排队任务独立记录用户提交时的冲突策略；原生任务锁、CSRF、进度验证和不确定结果处理沿用 v0.2.5.1。新功能已加入模拟原生协议测试；**真实 Unraid 上应先用临时文件验证覆盖及合并，不要直接操作重要资料。**

## v0.2.5.1：清晰显示复制前预检与全部同名冲突

- 批量任务开始执行时立即显示「正在检查复制任务…」，不虚构预检完成百分比。
- 目标目录存在同名文件或文件夹时，**全部冲突先收集、一次性展示**：弹窗正文顶部醒目展示冲突数量、所有冲突名称（列表限高可滚动）、本次没有开始复制的说明和下一步操作提示。

## v0.2.5：多任务排队与底部任务中心（方案 A）

- 可以依次建立多个独立复制任务（每项可以是单文件、文件夹或批量选择），当前 File Station 页面保持打开时按 FIFO 排队；**绝不并发提交两个 Unraid 原生复制任务**。
- 运行中的任务允许收起并继续选择源文件建立新任务；新任务不提前执行，轮到它时重新验证原生源目录与目标，继续保留拒绝同名、禁止覆盖与禁止不确定结果下重试的安全约束。
- 底部右侧采用紧凑方案 A：例如「复制中 25% ｜ ◷ 2」，百分比属于**当前正在执行的独立任务**，数字是尚未执行的任务数；无活跃任务时显示等待、完成或暂停状态。
- 点击右下角胶囊弹出任务中心，逐项显示运行中、等待中、完成、失败或待核实，点击任务恢复其原本的居中窗口；未开始任务可直接取消排队，**不触发 Unraid Control.php 写入或全局停止**。
- 任务失败（已提交或结果不确定）、安全停止时暂停后续排队，必须先核实再手动确认继续；**不重新执行失败任务**。安全预检失败属于无写入的可纠正错误，可更换目标重新排队。
- 已完成的任务保留结果入口，用户主动关闭结果后才从任务中心清除。队列仍在**当前浏览器页面**调度，刷新、关闭标签页或离开页面后不能可靠继续执行剩余任务。
- 本版不提供真正的原生任务并发、不持久化队列、不修改 Unraid 系统或创建后端服务。新增多任务顺序执行、排队取消和右下角状态的浏览器回归，实机仍需验收。

## v0.2.4：多项顺序复制与底部任务入口

- 支持从「操作 ▾」或右键菜单对多个文件及文件夹使用「复制到…」，复用既有目标目录树、行内新建文件夹、CSRF 检查和原生写入锁。单项复制入口及弹窗保持原流程。
- 批量开始前重新读取源目录及目标目录，对**整批**执行路径安全、原文件存在性、同名冲突及递归目标检查；任何预检失败都不发送写入，并允许重新选择目标位置。
- 原生复制只采用逐项顺序提交（文件 `action=8`、文件夹 `action=3`）；每项核验成功后才提交下一项。执行过程中如出现写入失败或结果不确定，立即停止剩余队列，不自动重试、不静默跳过、不覆盖。
- 批量主进度条显示**整个队列**的进度：全部普通文件且大小可信时按照总字节数加权；混合文件夹时按已核验完成项目加当前普通文件真实百分比计数（文件夹无递归大小时不虚构其部分进度）。100% 仅在全部项目核验成功后显示。
- 复制前只展示前三项摘要，点击「查看全部」进入独立清单视图；复制中可切换任务清单、搜索和查看逐项状态，列表最多同时渲染 500 项，可搜索定位更靠后的项目；固定 52px 弹窗标题及 64px 底栏。
- 复制中点击「后台运行」收起弹窗，**File Station 底部状态栏右侧**显示紧凑任务按钮；点击恢复相同复制窗口。完成、停止或待核实后保留结果入口，直至手动关闭。
- 「停止队列」默认允许**当前项完成后停止后续项目**，不触碰 Unraid 全局 `action=99`；可经警示确认、归属双重核验后尝试停止当前项目。后台仅意味着当前 File Station 页面运行，刷新或关闭浏览器后不会继续可靠调度后续项目。
- 本次不包含移动、删除、覆盖和自动重试；新增纯函数进度测试及 Playwright 批量复制、预检与后台任务回归，仍需真实 NAS 验收。

- **仅处理滚动**：对虚拟化文件列表和网格应用局部 `overflow-anchor:none`，避免 Chromium 在前后占位高度变动时自行修正 `scrollTop`、反复触发滚动，导致轻滚一次却持续下滑。
- 保留原生滚轮、触控板和滚动条；不改变滚动速度、不拦截 `wheel` 事件。普通文件列表、目录树、Unraid 原生 WebGUI 的滚动行为不受影响。
- Playwright 新增真实鼠标滚轮测试：单次 `wheel(0,380)` 后持续观察约 900ms，验证列表和网格的 `scrollTop` 不再自动增加；同时验证文件列表总滚动高度稳定。
- **本版不优化目录读取**：`Browse.php` 的完整 HTML 请求、网络等待及目录解析流程与 v0.1.15 保持一致，后续另行设计。

## v0.1.15：大目录虚拟列表和网格

- **虚拟列表**：单目录超过 200 项时，不再一次性创建每个文件对应的 DOM 行；仅渲染当前可视区域加前后 8 行的缓冲范围。通过前后占位高度保持真实滚动位置、列表的原生滚动条和固定表头。
- **虚拟网格**：网格视图同样按可视区域创建卡片，并随右侧区域宽度动态计算列数；文件项恢复列表时重新应用六列宽度。
- **保持完整数据**：过滤、排序、选中、Shift 跨窗口连选、⌘/Ctrl+A 和 LOCATION 均针对当前目录的完整数据集，不把未显示在 DOM 里的文件当作不存在；滚出屏幕后返回时恢复高亮。
- **减少重复计算**：按目录数组、筛选词、排序列与方向缓存排序结果，滚动时只更新窗口范围，不重复解析目录或重新排序。
- **仍不修改写入**：无数据库变更、不新增文件操作 API；小目录继续沿用原来的普通列表/网格渲染。
- 新增纯函数窗口边界测试、Playwright 1,200 项真实滚动与跨窗口多选测试，及 100 / 1,000 / 10,000 项大目录性能基准。

**首轮 Chromium 实测：**10,000 项目录从 v0.1.14 的约 **44.8 秒 / 13 万 DOM 元素**，改善为 v0.1.15 的约 **202 毫秒 / 445 DOM 元素**；1,000 项则由约 707ms 降到 84ms。测试详情和局限见 [v0.1.15 性能报告](docs/v0.1.15-virtualization.md)。

> 虚拟渲染固定使用列表行高 38px 和网格行步长 132px。后续 CSS 如果修改文件行实际高度，需同步这两个常量及回归测试，避免滚动定位错位。
## v0.1.14：导航稳定性、异步加载及真实浏览器测试

- 首次进入目录时增加初始化保护，避免在尚未创建标签页时触发后退、前进、新标签等操作。
- 统一 File Station 内部标签历史与浏览器历史：内部历史使用 `replaceState`，浏览器 `popstate` 只恢复目录和状态，不循环新增历史记录。
- 同一目录树路径的重复读取合并处理，错误不再缓存为“空目录”；切换当前目录时使用 `AbortController` 取消旧请求，防止慢请求覆盖新目录。
- 为全局事件监听、ResizeObserver、MutationObserver 与相关定时器建立退出清理机制；目录树展开箭头阻止事件冒泡。
- 新增 **Playwright Chromium 浏览器 E2E** 测试，实际检验根目录选择、浏览器历史、目录竞态、多选、LOCATION、列宽保存和加载失败重试。
- 已在模拟目录进行 100、1,000、10,000 文件性能实测，其中 10,000 项约 44.8 秒。后续应先引入虚拟列表优化，再进入真实写入阶段。
- 常规 GitHub Actions 运行单元测试和浏览器 E2E；大型目录基准已独立为手动工作流（合并到默认分支后可在 Actions 触发）。当前开发分支也可本地运行 `node tests/perf/benchmark.mjs`。

本次不改变 File Station 的外观、已有只读功能以及 NAS 部署方式。具体变更、真实测试记录和 v0.2 接口安全计划见 [v0.1.14 稳定性审查文档](docs/v0.1.14-stability.md)。
## v0.1.13：不可选的共享根分组与首次默认共享目录

- **所有共享文件夹只是分组**：左侧根节点仍可通过展开箭头展开或收起，但点击根节点文字不会导航或出现当前目录高亮。
- **首次默认目录**：从 Shares 页独立入口、直接访问 `/Shares/Browse?dir=/mnt/user` 或无 `dir` 参数时，先读取原生 Browse 返回的共享列表，再取左侧目录树顺序中的第一个有效共享目录打开（例如 TimeMachine），不依赖硬编码名称，也不按右侧文件列表的排序挑选。
- **无根目录闪屏**：取得共享列表后才创建标签页、加载对应共享内容。进入第一个共享时通过 `history.replaceState` 更新 URL，避免浏览器后退再次落在无法打开的根分组。

- **容错**：无共享目录时显示空状态，不生成虚假的根标签；根读取失败时显示错误并允许刷新重试。第一个共享目录无法读取时保留可切换的目录树入口。
- 保留 Unraid 顶部导航、两主题、列宽/LOCATION、多选、原生文件管理器回退和只读安全边界，不修改数据库或 Unraid 系统文件。

> 自动测试只能验证默认路径的计算和导航约束；还需在真实 Unraid 7.2.2 浏览器里验收根目录加载顺序、历史记录与闪屏行为。
## v0.1.12：列表滚动条与表格宽度边界优化

- **消除不必要的横向溢出**：表头和文件行使用统一的 `width:100%;min-width:var(--ufs-table-min-width);box-sizing:border-box`，不再使用 `width:max(100%,...)`。表格最小宽度仍然等于六列的配置宽度之和、五处间距和左右内边距；容器有足够空间时不应该出现横向滚动。
- **真实超宽仍能滚动**：用户保存的列宽较大、右侧详细信息展开、NAS 窗口缩窄时仍可使用原生横向滚动访问所有列，绝不简单剪裁 OWNER、权限或 LOCATION。
- **轻量纵向滚动条**：仅对右侧文件列表应用 6px 原生细滚动条；普通空闲状态滑块透明，鼠标悬停或滚动时显现，最后一次滚动约 1.1 秒后移除活动状态。浏览器/系统滚动条机制可能影响具体效果。
- **不改动原生滚动能力**：文件列表保持 `overflow:auto`；触控板、鼠标滚轮、键盘、拖动滑块和文件夹列表滚动继续有效，左侧目录树以及 Unraid 其他页面不受这次样式调整。
- **滚动尺寸诊断**：加入对 `clientWidth`、`scrollWidth`、可用高度、最小表格宽度和保存列宽的只读诊断函数及测试。在真实 NAS 上需确认水平溢出确实消失；如果历史保存列宽较大，可使用右上角菜单「重置文件列表列宽」。
- 只读安全边界不变，不新增写入请求、不调整已经解决的外层页面无限滚动算法。

> 自动测试只能验证宽度计算规则与行为，不代表已经远程测量你的 Unraid 7.2.2 浏览器。具体滚动条是否自动淡出以及是否存在实际 CSS 溢出，以实机为准。

### v0.1.2：修复页面无限向下滚动

- 修正高度计算使用视口坐标的问题：滚动时先将 `getBoundingClientRect().top` 换算为文档坐标，防止容器越滚越高。
- **仅在 File Station 增强版 Browse 页面禁用 HTML/body 外层纵向滚动**，文件列表、目录树和详情栏仍可独立滚动。
- 不再用 `ResizeObserver` 监听整个 `document.body`，避免由 File Station 自身高度变化造成的循环测量。
- 仍监听 Unraid 页面头部变化、视口变化和布局过渡，重新计算到原生底部状态栏之间的空间。
- 切回原生文件管理器会撤销增强版滚动限制；关闭用户脚本后 Unraid 页面不受影响。

**检查方法：** 打开 File Station 后滚动鼠标滚轮或触控板，Unraid 顶部导航和 File Station 顶部工具栏应保持可见；只有目录树或文件列表滚动，右侧页面外层不应出现无限变长的滚动条。顶部展开和收起都应重复检查。

### v0.1.3：清理工具栏滚动条和 Unraid 原生悬浮箭头

- 工具栏使用 `overflow-x:auto; overflow-y:hidden`，并隐藏滚动条的视觉轨道。屏幕较窄时仍允许横向滚动操作按钮。
- 在 File Station 增强模式下，隐藏 Unraid 的 `.move_to_end`（移至页尾）与 `.back_to_top`（回到页首）悬浮按钮。它们与文件管理器的内部滚动模式不兼容，而且会遮住状态栏。
- 使用 `html.ufs-active-page` 作用域限定该规则，离开 File Station 或切回原生 Browse 后不影响其他 Unraid 页面。
- 没有调整 v0.1.2 中已经确认稳定的页面高度算法，也没有增加文件写入请求。

**验收重点：** 工具栏最右侧不应出现短竖向滚动条，右下角的红色上下箭头不应压在 File Station 状态栏上；返回原生 Browse 后，原生页面滚动按钮应恢复。

- 范围限制在 File Station 的文件行和目录树，不影响地址栏、搜索输入框或 Unraid 其他页面。
- 不修改选中状态算法、固定工具栏、文件布局、动态高度及任何写入逻辑。

### v0.1.8：增加 OWNER 和 LOCATION 列

- 文件列表按 **名称 → 大小 → 修改日期 → OWNER → 权限 → LOCATION** 显示 6 列。
- OWNER 复用 Unraid 7.2.2 原生 Browse 接口已经返回的文件所有者（例如 root、nobody）。
- LOCATION 仅解析原生表格中的 `span[id^="device_"]` 设备名称，不混入磁盘加密状态图标或提示，也不会执行原生 HTML 的内联事件。支持多个磁盘/缓存池、去重以及未知位置时显示 `—`。
- v0.1.8 曾使用两个位置标签和 `+N`；这一展示方式已在 v0.1.9 被连续磁盘区间摘要与可查看全部设备的弹层替代。位置是设备名称，不是 `/mnt/user` 下的逻辑路径。
- OWNER 和 LOCATION 列支持升降序排列，仍优先显示文件夹；属性面板增加「存储位置」，区分「逻辑路径」。
- 根据可视区域自适应隐藏次要列：浏览器窗口在 981–1280px 时不显示权限和 LOCATION，在 980px 及以下进一步隐藏 OWNER；详情数据仍保留。这些阈值是 UI 设计值，需实机验证。
- 新增单位置、多位置、无位置、重复位置和排序测试；演示页面使用模拟设备位置数据。
- 保持只读，不查询额外后端、不推测数据实际落盘位置、不调整高度和多选逻辑。

**注意**：原生 Browse.php 本身可能根据共享配置提供回退设备信息，也可能对过长设备名进行截断。界面只展示接口实际可识别的设备标签，不承诺物理存储位置的完整性。Unraid 7.2.2 实机测试后再确认视觉表现。

### v0.1.9：详情按钮焦点、LOCATION 完整磁盘展示与表头居中

根据 Unraid 7.2.2 实机反馈完成以下三个界面修复：

- **详细信息按钮**：鼠标点击打开和关闭侧栏后不再留下橙色/黄色焦点框；按 Tab 使用键盘导航时仍保留可见焦点指示。
- **LOCATION**：不再使用「前两个磁盘 +N」隐藏剩余磁盘；改成完整且可读的摘要，如 \`disk2–disk4\`（包含 disk2、disk3、disk4）、\`disk1, disk3–disk5, cache\`。多个不连续磁盘保留各自编号。
- **完整位置弹层**：点击 LOCATION 摘要可以打开可滚动的完整磁盘/缓存池列表，适用于 4、20、50 甚至更多设备；鼠标悬停同样有完整名称提示。弹层支持点击空白处或按 Esc 关闭，不会改变文件选中状态。
- **列表布局**：LOCATION 摘要超过列宽时省略，行高始终固定，不会因磁盘数量增多而纵向膨胀。文件列表 6 个表头的文本和排序按钮统一垂直居中。
- 不改变原生读取、OWNER/LOCATION 排序、内部滚动、高度、文件操作或只读安全边界。

设备区间仅压缩连续 \`diskN\` 编号，不会臆造缺失的磁盘；例如 disk1、disk3、disk5 显示为三个独立位置。完整原始设备名称仍可在弹层看到。

## 安装（开发预览版）

1. 在浏览器中安装 Tampermonkey 或其他兼容的用户脚本管理器。
2. 打开 `src/unraid-file-station.user.js` 的 Raw 地址，安装脚本。
3. **建议在用户脚本管理器中将匹配地址收窄为自己的 NAS 主机名或 IP。** 默认规则匹配任何主机上的 `/Shares*` 路径，仅为兼容不同 Unraid 主机名。
4. 打开 Unraid 7.2.2 的 **SHARES** 页，点击共享名称左边的蓝色浏览图标；或者点击 Shares 下方新出现的 **FILE STATION** 按钮。
5. File Station 右上角的 **返回原生** 可以恢复原生文件管理页面；原生页面上会有 **打开 File Station** 按钮用于切回。

示例：如果你的 Unraid 地址是 `http://tower`，可将用户脚本头部的通用匹配规则改为：

```javascript
// @match        http://tower/Shares*
// @match        http://tower/Main/Browse*
```

如果使用 IP、端口、HTTPS 或自定义域名，请相应调整。不要直接使用示例地址覆盖自己的 NAS 地址。

**脚本只向同源 Unraid WebGUI 发送目录读取请求**，不需要 API Key、数据库、额外 Docker 容器或 NAS root shell 权限。尽管当前只读，也建议先在非关键目录试用。

## 技术与安全原则

- **不更改 Unraid 系统文件**，通过浏览器用户脚本实现可逆接入。
- **只读优先**：当前所有文件操作请求只有 GET 目录请求；下载采用原生文件 URL，写入功能暂不调用 `Control.php`。
- **路径边界**：只允许 `/mnt/user` 及其子目录，不让用户共享与物理磁盘路径互相拖放。
- **视图与数据隔离**：动态文件名使用 `textContent` 渲染，不直接拼入 HTML 字符串。
- **同源请求**：使用已有 Unraid 登录会话，无第三方上传或数据收集。
- **回退开关**：浏览器保存用户偏好，关闭/卸载脚本立即恢复原生 WebGUI。
